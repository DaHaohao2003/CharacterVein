# 五分钟比赛演示脚本

> 状态：目标演示脚本。需在阶段 8 功能全部验收后用于正式录屏，当前不可把尚未实现的叙事路线与三类传播成品描述为已完成。

主演示案例使用“礼”。它既能展示真实历代字形，也能自然连接当代生活中的尊重、秩序和人与人之间的分寸。演示目标不是证明系统知道多少文字学知识，而是证明智能体能把汉字文化素材转化为适合具体人群和媒介的传播作品。

## 开场句

> 今天我不让 AI 只写一篇“礼”字讲解，而是请它完成一项文化传播任务：自己寻找文化切口，选择合适字形，并为三种媒介创作一套统一的内容。

## 0:00—0:35 传播任务输入

输入：

> 围绕“礼”制作一套面向年轻人的汉字文化内容，用于互动长页、五张图文卡片和 60 秒短视频，有文化感但不要太学术。

展示系统提取的 CommunicationBrief：目标字、传播目标、目标受众、媒介、表达风格、时长、交付物与成功标准。可附加一份活动背景文档，说明上传材料只服务于当前任务。

## 0:35—1:15 智能体开始探索

进入工作台，重点展示而不是逐项朗读：

- 当前正在回答的文化探索问题；
- 剩余搜索、字形重选和成品返工预算；
- Agent 在白名单中选择的下一动作；
- 一句面向用户的决策摘要，例如“现有资料能解释历史背景，但缺少与年轻人日常生活的连接，因此改写查询继续搜索”。

说明外层 LangGraph 负责状态、预算和终止，模型负责在允许动作中决定下一步。它不是写死的八步流水线，也不会无限循环。

## 1:15—2:10 字形成为视觉叙事素材

沿历史主时间线查看真实代表字形，再查看独立草书支线和同文体异体图库。展示 `qwen3.8-flash` 对已标注字形的可见观察，以及 Agent 选出的视觉钩子。

演示话术：

> 这些图片不是现代字体模拟，而是存于 PostgreSQL/MinIO 的 JieZi 样本。视觉模型不猜这是什么字，也不判断必然传承；它观察轮廓、构件位置、疏密和线条变化，再把适合开场、对比或互动的图片交给叙事 Agent。

若展示阶段对比，明确七类目录是样本分类，不把它们描述为无分支的严格年代直线。

## 2:10—2:50 资料探索与停止决策

展示本次真实读取的网页片段与用户资料位置，以及查询改写或停止决策。说明：

> 这些材料是模型本次创作的参考上下文。系统展示“参考了什么”，但不做来源等级评定、逐句证据绑定或事实核验。

正式演示必须使用真实 Web Search 或用户上传资料，不能把 Stage 7 fixture 冒充网络搜索结果。

## 2:50—3:35 多条文化叙事路线

同时展示 2–3 条差异化路线，例如：

1. **从字形看见礼**：以构形变化和视觉对比为线索；
2. **礼如何进入日常生活**：从古代规范连接当代相处方式；
3. **礼不是距离，而是分寸**：用一个当代问题制造讨论感。

打开路线卡片，展示核心信息、开场钩子、故事节拍、当代连接、建议字形和适用媒介。选择其中一条，说明用户可以主动选择，也可以接受 Agent 推荐；确定后才形成统一文化母题。

## 3:35—4:35 一套母题，三种传播表达

切换到文化传播页，依次快速展示：

- 互动文化长页：滚动叙事、字形视觉顺序和观众互动问题；
- 五张图文卡片：每张承担不同故事节拍，适合连续发布；
- 60 秒短视频：分镜、画面建议、旁白、字幕和节奏点。

指出三类成品不是同一篇文章换格式，而是共享核心信息、文化母题和视觉序列，各自遵守媒介结构。

## 4:35—5:00 定向返工与收束

把第 3 张卡片改为“表达更年轻，但不要网络热梗”。展示系统只重写该卡片，不重新搜索、不重跑多模态观察，也不覆盖旧版本。最后展示传播目标验收、参考资料记录和导出。

收束句：

> 字脉的价值不是替人查完一个字，而是让汉字文化从资料和古文字图片出发，经过智能体的探索、选择与跨媒介创作，真正变成今天的人愿意看、愿意理解、也愿意分享的文化故事。

## 现场备用方案

- 保留一个使用真实模型与真实资料完成的“礼”任务，只用于现场网络中断时回放，必须标明是已完成任务；
- 外部模型失败时显示 provider、失败节点和可恢复状态，不假装仍在实时生成；
- 页面断线后重新打开原任务 URL，展示 PostgreSQL 检查点恢复；
- 四字原图、元数据和向量均在本地 PostgreSQL/MinIO 卷中；
- `glyph-seed` 幂等复用 328 个对象，重新建容器不重复导入；
- “云、雷、明”只用于证明同一架构可复用，不在五分钟内逐字浏览功能。
