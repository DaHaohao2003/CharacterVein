# 阶段 7 智能体评测规范

## 目标

阶段 7 不做模型基线对比或消融实验，只验证比赛演示所需的智能体闭环是否真实、可追踪并能安全失败。

## 检索集

- 20 条黄金查询：云、雷、礼、明各 5 条；
- 覆盖数据集总览、甲骨文字形、金文字义/分期、楷书规范形和草书支线；
- 指标为 Recall@10，验收阈值为 95%；
- 每条结果必须至少记录结构化、关键词或向量通道排名以及 RRF 分数。

黄金查询固化在 `apps/api/tests/test_stage_seven_agent.py`，避免只凭页面观感判断检索质量。

## 智能体场景

| 场景 | 输入条件 | 期望行为 |
| --- | --- | --- |
| 正常 | 四字可信语料完整 | 动态九步计划、六类工具轨迹、陈述级绑定、审校通过、约束通过 |
| 证据不足 | 文献检索返回空结果 | 根据审校问题重试一次；仍不足则拒绝无证据陈述、任务部分完成并请求用户确认 |
| 证据冲突 | 审校检测到相互冲突或低等级证据 | 陈述降级，不把争议写成定论；其余安全内容可以继续生成 |
| 节点中断 | 工具第一次调用抛出异常 | 通过 LangGraph 检查点从失败节点恢复，不重复已完成节点 |

## 验收命令

```powershell
docker compose --env-file .env -f infra/compose.yaml run --rm --no-deps --entrypoint uv api run --project apps/api pytest -c apps/api/pyproject.toml
```

正式验收记录必须同时包含 Python 测试、Ruff、Mypy、前端 ESLint/Prettier/Next 构建以及浏览器端正常案例检查。

使用真实嵌入配置时，还必须单独运行 `evidence-seed`，并确认输出包含 68 条文献、7 次分批请求和 `embedding_fallback=false`。这用于防止“文献向量已本地降级、查询向量仍来自云端”造成两个向量空间不一致。
